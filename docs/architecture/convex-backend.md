# Convex Backend

Last verified: 2026-07-04 (post cleanup/reorg commit).

**Before editing any Convex code, read `convex/_generated/ai/guidelines.md` first** — it documents API/pattern rules that override general Convex training knowledge.

## Schema (`convex/schema.ts`)

Key tables (non-exhaustive, grouped by domain):

- **Users/auth**: `users`, `testLinks`
- **Catalog**: `products`, `productReviews`, `stages`, `tiers`, `reels`, `reelProducts`, `brands`, `collections`, `productRelations`
- **Cart/Wishlist**: `cartItems`, `wishlistItems`, `cartAbandoned`
- **Registry**: `registries`, `registryItems`, `registryNotifySignups`, `registryContributionPayments`
- **Orders/Checkout**: `orders`, `orderItems`, `coupons`, `checkoutSteps`, `checkoutConfirmationPromos`, `checkoutTrackingStages`, `checkoutTrackingRider`, `deliveryZones`, `deliveryLandmarks`, `refunds`
- **Dashboard/Engagement**: `dashboardItems`, `dashboardMilestones`, `dashboardBadges`, `dashboardChecklists`, `dashboardEditorial`, `loyaltyTransactions`, `npsScores`, `surveyResponses`, `referrals`
- **Misc**: `hero`, `trustItems`, `subscriptions`, `searchHistory`, `supportTickets`

## Backend function files (`convex/*.ts`)

One file per domain, matching the schema groupings above: `products.ts`, `cart.ts`, `wishlist.ts`, `registry.ts`, `orders.ts`, `brands.ts`, `coupons.ts`, `users.ts`, `data.ts` (misc/shared queries), `emails.ts` (transactional email), `migrations.ts` (schema/data migrations), `seed.ts` (dev seed data), `inspect.ts` (debug helpers).

## Payments (Pesapal)

- `convex/pesapal.ts` — order checkout payment flow.
- `convex/registryPesapal.ts` — registry contribution payment flow (separate from order checkout).
- `convex/http.ts` — HTTP routes, including Pesapal IPN/callback handling consumed by `src/pages/PaymentCallbackPage.jsx`.

## Auth

- `convex/auth.ts` + `convex/auth.config.ts` — Convex Auth configuration.
- `convex/auth_test.ts` — auth-related test/debug helpers.
- Frontend auth flow: `src/pages/AuthPage.jsx` → `src/pages/AfterSignIn.jsx`; protected routes wrapped by `src/components/layout/ProtectedRoute.jsx`.

## Adding a new backend function

1. Check `convex/_generated/ai/guidelines.md` for current API conventions (query/mutation/action signatures, validators, etc.).
2. Add/update the table shape in `convex/schema.ts` if new data is needed.
3. Add the query/mutation/action to the matching domain file (e.g. a new registry mutation goes in `convex/registry.ts`, not a new file).
4. Regenerate types if needed — `convex/_generated/api.d.ts` is auto-generated by the Convex dev/deploy process, don't hand-edit it.
